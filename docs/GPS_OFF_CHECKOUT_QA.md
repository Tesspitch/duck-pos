# ตรวจสั่งโต๊ะเมื่อปิดตำแหน่ง — 6 พฤศจิกายน 2026

ทดสอบ Chromium ที่ viewport มือถือ 390×844 และแท็บเล็ต 768×1024 โดยตั้งสิทธิ์ geolocation เป็น `denied` จริง ใช้หน้าและ hooks ของแอปจริงกับ repository จำลองที่แยกจาก production บริการขอตำแหน่งเป็น `browserCustomerLocationService` ตัวจริง จับจำนวนการเรียก `getCurrentPosition` ของเบราว์เซอร์ และจำลองเหตุการณ์ Realtime ข้ามแท็บด้วย storage events

ผลผ่านทั้งสองขนาด:

1. สแกน QR โต๊ะ เข้าเมนู เลือกขนาด M ส่งครั้งแรก และสั่งเพิ่มอีกครั้งได้ จำนวนการเรียก GPS = 0
2. หน้าคิวพนักงานที่เปิดค้างไว้แสดงคิว 001 และ 002 อัตโนมัติ พร้อมชื่อโต๊ะ เมนู ขนาด และราคาครบ โดยไม่กดรีเฟรช
3. พนักงานกดเริ่มทำและเสร็จแล้ว รายการยังอยู่ในคิวระหว่างรอชำระ
4. รับชำระรวมเงินโอน 98 บาท คิวหมด และลิงก์ลูกค้าเดิมแสดงว่าชำระเสร็จสิ้น
5. QR หน้าร้านในเบราว์เซอร์ที่ปิดสิทธิ์ GPS ถูกปฏิเสธ จากนั้นอนุญาต GPS และตั้งตำแหน่งนอกพื้นที่แล้วถูกปฏิเสธอีกครั้ง ไม่มีออเดอร์เพิ่ม
6. หน้า Admin แสดงร้านเปิดและร้านปิด พร้อมปุ่มปิดร้านสำหรับร้านเปิด
7. กดออกจากระบบพบหน้าต่างยืนยัน กดอยู่ต่อยังไม่ออก และออกจริงเมื่อยืนยันเท่านั้น

ตรวจฐานข้อมูลจริงแยกต่างหากโดย rollback ทุก fixture: SQL 0030 (15), 0029 (40), 0020 (15), 0027 (46) ผ่าน รวม 116 ข้อ ยืนยันไม่มี GPS ในเส้นทางโต๊ะ แต่ QR หน้าร้านยังตรวจพิกัด 100 เมตร คิวและรับชำระถูกต้อง ไม่ได้ทำธุรกรรมทดสอบในร้านจริง หรือทดสอบเครื่อง iPhone/iPad จริง

หลักฐานในเครื่อง (ignore จาก Git ตามที่ผู้ใช้ขอ): `artifacts/qa/gps-off-flow-results.json` และ `artifacts/qa/screenshots/gps-off-*`

## สถานะร้านใน production

ตรวจไฟล์ที่เสิร์ฟจาก `https://duck-pos-ack.pages.dev` พบ entry `/assets/index-1GGIApV3.js` และ `/assets/PlatformAdminPage-DVMA-t7b.js` มีข้อความสถานะร้านและขั้นตอนยืนยันปิดรอบขาย ตรวจนิยาม `list_platform_shops` บนฐานข้อมูลจริงพบทั้ง `isOpen` และ `activeSessionId` แล้ว ภาพที่ผู้ใช้ส่งยังไม่แสดง badge จึงอาจเป็นแท็บหรือ frontend รุ่นก่อนที่ค้างอยู่ ยังไม่ยืนยันสาเหตุ cache จากเครื่องผู้ใช้โดยตรง ให้รีโหลดหน้าเพื่อรับไฟล์ปัจจุบัน

## เปลี่ยนโค้ด

`SignOutConfirmation.tsx` แยก dialog ยืนยันออกจากระบบ มีปุ่มอยู่ต่อ ป้องกันกดซ้ำระหว่างส่ง และแสดงข้อผิดพลาดให้ลองใหม่ `AppShell.tsx` เปิด dialog จากเมนูทุกขนาดจอแทนการออกทันที ทดสอบการยกเลิก ยืนยัน และเครือข่ายขัดข้องใน `AppShell.test.tsx`

ต้อง deploy frontend ใหม่เพื่อใช้การยืนยันออกจากระบบ ไม่มี migration หรือ Edge Function เพิ่มในงานรอบนี้

ตรวจท้ายงาน: `npm run verify:production` ผ่าน ทั้ง lint, Vitest 41 ไฟล์ 136 ข้อ และ production build/PWA
