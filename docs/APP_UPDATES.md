# การแจ้งเวอร์ชันใหม่และรักษางานที่กำลังทำ

แอปแสดง **มีเวอร์ชันใหม่** พร้อมปุ่ม **อัปเดต** และ **ไว้ก่อน** ผู้ใช้เป็นคนเลือกเวลาโหลดใหม่ หากเลื่อนไปก่อนจะเหลือปุ่มเล็กสำหรับเปิดแจ้งเตือนอีกครั้ง

## พฤติกรรม

- ใช้ service worker แบบ prompt ปิด automatic activation/registration ของ plugin และใช้ตัวจัดการ native ที่ไม่รีโหลดแท็บอื่นเอง
- ตรวจเวอร์ชันเมื่อเปิดแอป กลับมาที่แท็บ หรือกลับมาออนไลน์ และทุก 15 นาทีเฉพาะแท็บที่มองเห็น การตรวจจากเหตุการณ์มีช่วงห่างอย่างน้อย 60 วินาที
- ห้ามอัปเดตขณะ mutation ค้าง รวมช่วงขอตำแหน่งก่อนส่งออเดอร์ ห้ามอัปเดตเมื่อเปิดหน้าต่างทำรายการหรือมีฟอร์มที่แก้ไขค้างอยู่ ให้บันทึกงานและเปลี่ยนหน้าก่อน
- ก่อนเปิดใช้ worker ใหม่ เขียนตะกร้าลูกค้าและ POS ลง sessionStorage ให้สำเร็จ หากเก็บไม่ได้จะไม่ activate หรือ reload
- ตะกร้าลูกค้าเก็บหมายเหตุทั้งออเดอร์และ checkout identity เพิ่มเติม การลองส่งคำขอเดิมหลังโหลดใหม่ใช้ idempotency/tracking token เดิม POS เก็บรายการ หมายเหตุ และ request ID เดิม
- ข้อมูลรอบโต๊ะและลิงก์ติดตามใน localStorage ไม่ถูกล้าง ออเดอร์ที่ส่งแล้วอยู่ใน PostgreSQL ตามเดิม หลังโหลดใหม่อ่านสถานะล่าสุดจาก backend
- ไม่อัปเดตตามผู้ใช้อีกแท็บโดยการรีโหลดแท็บของเรา การส่งคำขอในแท็บนั้นจึงดำเนินต่อได้ ไม่ cache ข้อมูลบิล/สิทธิ์ผ่าน CDN หรือ service worker เพิ่ม

## ไฟล์

- `src/shared/application/app-updates.ts`: ขอบเขตตัวจัดการเวอร์ชัน
- `src/shared/infrastructure/browser-app-updates.ts`: ลงทะเบียน ตรวจ worker และ activate ตามการกด
- `src/shared/application/update-safety.ts`: ป้องกันการตัดการทำรายการและฟอร์มค้าง
- `src/shared/application/preserve-update-drafts.ts`: เก็บตะกร้าก่อนโหลดใหม่
- `src/shared/presentation/AppUpdateNotice.tsx`: แจ้งเตือนและสถานะระหว่างอัปเดต
- `vite.config.ts`: prompt mode, ไม่มี automatic skipWaiting/clientsClaim

## ผลตรวจ

ทดสอบด้วย production build A และ B และ service worker จริงบน Chromium ที่ 390×844 และ 768×1024: แจ้งเตือนเมื่อมี worker ใหม่ ไม่ activate เอง ปุ่มถูกปิดเมื่อมีฟอร์มหรือ HTTP mutation ค้าง กดอัปเดตแล้วโหลดรุ่น B ตะกร้าลูกค้า/POS หมายเหตุ request IDs และลิงก์โต๊ะตรงกับก่อนอัปเดต อีกแท็บยังอยู่รุ่น A พร้อมข้อความฟอร์มเดิม คำขอ HTTP ที่กำลังรอไม่ถูกตัดและจบได้ จากนั้นกดอัปเดตแท็บนั้นได้โดยไม่สร้างคำขอซ้ำ

หลักฐานในเครื่องซึ่ง ignore จาก Git: `artifacts/qa/pwa-update-results.json` และ `artifacts/qa/screenshots/pwa-update-*` ใช้ข้อมูลจำลอง ไม่ใช่ธุรกรรมร้านจริง และยังไม่ได้ตรวจบน iPhone/iPad จริง

มี unit tests สำหรับการเลือกอัปเดต การเลื่อน การบล็อก GPS/mutation/form/dialog, storage failure, การ rehydrate ตะกร้า และ worker อีกแท็บ activate โดยไม่ reload แท็บนี้

ตรวจท้ายงาน: `verify:production` ผ่าน lint, ชุดทดสอบ 43 ไฟล์ 144 ข้อ และ production build/PWA จากนั้นเพิ่มและรันข้อทดสอบการ rehydrate รหัสคำขอพร้อมหมายเหตุอีกหนึ่งข้อผ่าน (ไฟล์ cart-store รวม 3 ข้อผ่าน)

## นำขึ้นใช้งาน

deploy frontend ใหม่ตามกระบวนการเดิม ไม่มี migration หรือ Edge Function เพิ่ม รุ่นก่อนที่ยังไม่มีตัวแจ้งเตือนต้องทำรายการที่ค้างให้เสร็จ แล้วรีโหลดแบบข้าม cache ในแท็บเดิมหนึ่งครั้งเพื่อรับรุ่นนี้ อย่าปิดแท็บที่มีตะกร้าค้างเพราะตะกร้าใช้ sessionStorage จากนั้นการอัปเดตรุ่นต่อไปจะแสดงแจ้งเตือนเอง
