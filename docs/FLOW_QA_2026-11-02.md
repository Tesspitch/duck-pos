## ข้อบกพร่องที่แก้

- AuthGate เคย redirect หน้าของ Owner ก่อน ActiveShopProvider โหลดสาขาครบ แก้ให้รอข้อมูล แล้วทดสอบ direct link ครบทั้งสามขนาดจอ
- ล็อกจำนวน การลบ และหมายเหตุระหว่างส่ง POS/checkout พร้อมป้องกันส่ง POS ซ้ำก่อน UI render รอบถัดไป
- ปิดหน้าตะกร้าเมื่อลบรายการสุดท้ายทั้งลูกค้าและ POS เพื่อไม่เปิดค้างเมื่อเพิ่มรายการใหม่
- จำกัดจำนวนให้เป็นจำนวนเต็ม 1–20 และไม่รับ NaN/Infinity ใน cart store
- แสดงเหตุผลบนปุ่มที่ยังปิดออเดอร์ไม่ได้ และแสดงสถานะคืนเงินถูกต้อง
- เพิ่มปุ่มลองใหม่ให้เมนูและ tracking เมื่อเครือข่ายผิดพลาด แยกออกจากกรณีไม่พบ token
- จัดสินค้า/จำนวนในตะกร้าแท็บเล็ตให้อยู่แถวเดียวเมื่อพื้นที่พอ
- เพิ่ม feedback เมื่อคัดลอก/สร้าง PNG ไม่สำเร็จ และสถานะกำลังสร้าง PNG
- ใช้ migration `202611020028_validate_checkout_coordinates.sql` บน Supabase แล้ว: ปฏิเสธพิกัดว่าง นอกช่วง และ NaN ทดสอบระยะนอก 100 เมตร ความแม่นยำต่ำ ตำแหน่งเก่า ราคา authoritative และ token isolation หลัง migration ผ่าน พร้อมทดสอบราคาซอส QR/POS ซ้ำ

ไม่มี dependency ใหม่ และไม่เพิ่ม polling/subscription การตรวจพิกัดเพิ่มเฉพาะ checkout ไม่เพิ่ม query

## ขอบเขตที่ยังไม่รับรอง

- ยังไม่ได้ส่งออเดอร์/บันทึกเงินผ่าน UI จริง ข้อมูลธุรกรรมทดสอบผ่าน repository จำลองและ SQL rollback เพื่อไม่ปะปนยอดขายร้าน
- ยังไม่ได้ทดสอบ GPS permission, Google OAuth redirect และ checkout บนโดเมน HTTPS production หรือ Safari/iOS/Android เครื่องจริง รวมถึงคีย์บอร์ดบนจอ
- QR แสดงผลสำเร็จ แต่การจับ download event ของเบราว์เซอร์ค้าง จึงยังไม่รับรองการดาวน์โหลดไฟล์ผ่าน UI จริง; component tests ของการสร้าง/ส่งลิงก์ดาวน์โหลดและการกู้คืนข้อผิดพลาดผ่านแล้ว
- ไม่ได้ทดสอบการส่ง LINE ไปยังผู้รับจริงรอบนี้ และยังต้องตรวจ production domain/CORS, backup/restore และ post-deploy smoke ตาม production runbook

ผลนี้ยืนยัน flow และข้อแก้ไขตามหลักฐานข้างต้น ยังไม่ใช่การรับรอง production end-to-end ครบทุกอุปกรณ์
